# Battery Life

Уровень заряда беспроводных устройств в системном трее KDE Plasma на Wayland. Нажмите значок батареи, чтобы открыть список и запустить проверку заряда. В меню название устройства слева, заряд или статус справа. Источник данных и время замера видны в подменю каждого устройства. В разделе «Настройки» находятся «Открыть окно», «Ориентация значка» и «Стиль значка». Выбор ориентации и стиля сохраняется после перезапуска. Для запуска сразу с окном есть параметр `--window`.

Автоматическая проверка выполняется каждые 30 секунд. Кроме устройств с отдельной поддержкой, Battery Life показывает беспроводную периферию, заряд которой доступен через BlueZ или UPower.

В списке появляются только устройства, которые Battery Life уже обнаружила. После отключения показывается последнее известное показание с пометкой «отключено». Если приёмник виден, но состояние устройства определить не удалось, сохранённое показание помечается как «устарело». История сохраняется между запусками в `$XDG_STATE_HOME/battery-life/devices.json` (по умолчанию `~/.local/state/battery-life/devices.json`).

При 15% и ниже, а также при уровне «Низкий» или «Критический», Battery Life показывает предупреждение в трее и отправляет системное уведомление. Пока устройство сообщает низкий заряд, напоминание повторяется примерно раз в час. Зарядка или восстановление уровня до 25% сбрасывают таймер для следующего предупреждения.

## Запуск на Fedora KDE

1. Скачайте файл **Battery-Life-x86_64.AppImage** из [последнего релиза](https://github.com/skyarse/Battery-Life/releases/latest).
2. В каталоге с AppImage выполните команды ниже. Если значок скрыт, раскройте системный лоток Plasma.

```sh
chmod +x Battery-Life-x86_64.AppImage
./Battery-Life-x86_64.AppImage
```

Если система сообщает, что FUSE недоступен, используйте `./Battery-Life-x86_64.AppImage --appimage-extract-and-run`.

### Доступ к приёмникам

Если приложение показывает «Нужны права доступа», один раз добавьте правила для активного локального пользователя. Затем переподключите USB-приёмник или переподключите геймпад по Bluetooth.

```sh
./Battery-Life-x86_64.AppImage --print-udev-rules > 70-battery-life.rules
sudo install -m 0644 70-battery-life.rules /etc/udev/rules.d/70-battery-life.rules
sudo udevadm control --reload-rules
```

Само приложение запускается от обычного пользователя. Команда `--diagnose` печатает состояние всех пяти устройств и список HID-интерфейсов без серийных номеров и MAC-адресов.

## Устройства

| Устройство | Источник данных |
| --- | --- |
| ZAOPIN Z2 Max | Compx 2,4 ГГц. Поддержка реализована по описанию протокола и требует проверки на этой модели. |
| Logitech G304 | LIGHTSPEED HID++. Приблизительный процент, который сообщает мышь. |
| 8BitDo Pro 2 | Bluetooth в режиме X. Системный заряд или уровень из совместимого отчёта геймпада. |
| CIY Tester 68 | Только системный источник. Чтение заряда через приёмник 2,4 ГГц пока не подтверждено. |
| MCHOSE V9 PRO | Приёмник 2,4 ГГц сообщает приблизительный уровень ступенями по 10%. При подключении кабеля отображается статус зарядки. |

Подробности о поддержке и источниках приведены в [описании протоколов](docs/PROTOCOLS.md).

## Сборка

Для локальной сборки на Fedora нужны Rust, компоновщик, `pkgconf-pkg-config` и `fontconfig-devel`. Окно Slint работает через Wayland. Меню рисует Plasma через StatusNotifierItem (`ksni`).

```sh
cargo test --locked
cargo run --locked -- --diagnose
cargo run --locked
```

GitHub Actions собирает AppImage для x86_64 и проверяет запуск. После успешной сборки в `main` новая версия из `Cargo.toml` публикуется в GitHub Releases вместе с контрольной суммой. Увеличьте версию пакета и обновите `Cargo.lock`, чтобы выпустить следующий релиз.
